实现：`src/world/buildings/merge.js` 给 `GeoBuilder.box()` 加了 **uvWorld 模式**——
UV 不再按"每个盒子各自 0..1 铺一遍"，而是按楼体局部坐标（米）投影：`v=(y-立面起点)/层高`，
`u=±x或±z /开间`。这样一段墙的分格由真实尺寸决定，多段墙体（图书馆两翼、中原 7 段折面、
会堂柱廊后墙）自动连续，不会出现"盒子越高窗户越拉长"。

`v` 的起点取"第一段墙体的底"（`vAnchor`）：逸夫 2.6m 石材基座、文泰 3.2m 基座这种楼，
从 ±0 起算会整体错半层，锁到基座顶后正好层层对齐。

### 5.3 兜底（三条都实测过）

1. **manifest 缺项 / 非真照片** → 不建私有 kit，整栋走原共享材质桶，观感与 draw call 都不变（58 栋已常态验证）。
2. **贴图解码失败**（把 逸夫图书馆 的 base64 改成坏数据实测）→ `onError` 里抽掉 `map/emissiveMap`，
   退成 manifest 的 `wallColor` 纯色石材：不白屏、不黑块、楼体结构完整（work/shots/fallback_lib.png）。

   其余桶照常合并，不会丢楼。

## 6. 2026-11-11 视觉返修（黑穹顶 / 天空 / 广场 / 玻璃 / 体育馆曝光）

### 6.1 黑穹顶 = 远平面裁掉天空（最刺眼 bug，已修）

现象：体育馆南面抬头能看到一块巨大纯黑穹顶，遮住后面的教学楼与宿舍。
定位过程：隐藏 far-hills 无效 → 把清屏色改成洋红 `setClearColor(0xff00ff)`、只留天空 mesh，
黑区读出 `[255,0,255]`（纯清屏色），而正常天空区读出 `[207,219,234]` → 天空根本没画到那里。
根因：`src/core/sky.js` 天空球 `SphereGeometry(1900,40,24)` 球心固定在原点；
相机走到校园北缘（z≈470）时远端球面距 ≈ 1900+470 = 2370 > `camera.far:2200`（`src/core/config.js:12`），
被远平面裁出一个洞，露出黑色清屏色。

修法（三处）：
1. `src/core/config.js:12` `far: 2200` → `3000`；
2. `src/core/sky.js` `update(t)` → `update(t, camera)`，内部 `dome.position.copy(camera.position)`，
   天空球跟着相机走，半径恒定 1900，永远在远平面内；
3. `src/main.js:671` 调用处补 `camera` 实参。

顺带修了天空的「浅色矩形」：`fbm2()` 每个八度加了旋转矩阵
`mat2 rot = mat2(0.80,0.60,-0.60,0.80)`，消除 value-noise 的方形栅格。
验证：work/shots/fix_dome.png、fix_sky.png。

### 6.2 五羊广场整片发黑 = 实拍墙面在投影阶段变成大遮挡体（已修）

现象：出生点脚下 2/3 屏幕是发黑的「棋盘格」，远处草地却是亮的。
定位过程（走了不少弯路，记下来免得重犯）：
- 先怀疑阴影：关 `receiveShadow` → 变亮；关 `shadowMap` → 仍暗（材质没重编译，误判）；
- 把广场材质换成纯洋红 → 整片变亮，说明**光照没问题，问题在贴图/阴影二选一**；
- 最后用 `readPixels` 逐个别打开 232 个 caster 的 `castShadow`，只有
  `bld-photo-逸夫图书馆` 一个能把地面像素从 (99,90,77) 压到 (39,45,46) → 锁定。

根因：`emitPhoto()` 里的实拍墙面 mesh 是世界坐标几何 + `matrixAutoUpdate=false`，
进 shadow pass 后变成一个横跨全场的大遮挡体，把整片广场压成阴影。
修法：`src/world/buildings.js` 里该 mesh 改 `castShadow = false`（楼体本身在
`wClassic/wModern` 共享桶里已经投过影，关掉不丢影子）。
验证：work/shots/fix_plaza.png、spawn_final.png —— 广场恢复暖米色石铺。

### 6.4 图书馆中庭玻璃去饱和

`src/world/buildings/photo-accurate.js` buildYifu：中庭 0x547f8b、顶层玻璃盒 0x6f9aa8、
端部幕墙 0x6c94a4 → 全部改暖灰 0x9a948c / 0x8e8880 / 0x968f87。
原因：`M.glass` 无环境贴图，半球光 `#bcd6ee` 偏蓝，sRGB→linear 后蓝通道被放大，
必须用**暖灰**去抵消，否则渲染出来是卡通饱和蓝。

### 6.5 体育中心曝光：改成「照片当主光源」

南面被太阳直射糊成白、北面发闷。改为 `{albedo:0x6a6a6a, emissiveIntensity:0.62}`

### 6.6 教训

- **判断颜色一律用 `tools/shot.sh` 截图**：`r.render()` 直出与 post 合成（HDR RT + bloom）
  颜色差很多，`readPixels` 只能用来做「A/B 相对亮度」比较，不能当最终颜色。
- 运行时改 `renderer.shadowMap.enabled` 不会自动让材质重编译，必须遍历材质置
  `needsUpdate = true`，否则会得出错误结论。
- `r.setRenderTarget(null)` 后再 `r.render(scene, cam)`，否则读到的是 RT 里的旧内容。
